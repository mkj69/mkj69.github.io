01 / CENTRAL QUESTION

Does adding agents
make a system smarter?

THE SHORT ANSWER

Not necessarily. Team size alone is not a scaling variable with a universal positive return. The effect depends on who the agents are, what they exchange, whether the task splits cleanly, and what budget they share.

More samples ≠ more collaboration.

Independent votes can improve an ensemble without any communication. Interactive multi-agent systems pay additional coordination and context-transfer costs.

The baseline is the counterfactual.

Compare against a strong single agent with self-consistency, retries, search, and verification under the same per-system budget.

RESEARCH OBJECTIVECONCEPTUAL FORMULATION · NOT A FITTED LAW
Quality = f(model, agents, graph, policy, task, budget)

More precisely: maximize verified quality subject to total tokens, wall-clock time, tool calls and failure risk. The optimal agent count n* can be one.

●●●●

Scaling samples

Independent completions → selection or voting. Gains require nontrivial correctness and imperfectly correlated errors. This is not coordinated work.

●●●●

Scaling organizations

Delegation → communication → synthesis and verification. Can expand search and parallelism, or lose information and amplify mistakes.

A critical version note

The December 2025 preprint / January 2026 Google blog reported 180 configurations, four benchmarks and cross-validated R² = 0.513. The July 24, 2026 journal version evaluates 260 configurations, six benchmarks and reports R² = 0.373 (0.413 with a task-grounded capability metric). Its ~45% capability threshold is explicitly a validated selection heuristic, not a universal scaling law; several directional trends do not survive cluster-robust correction. We use the later published version for headline claims.

03 / THE MECHANISMS

Count is an input.
Structure is the lever.

Six interacting dimensions explain why identical agent counts can have radically different outcomes.

01

Model capability

As a base model improves, the marginal value of splitting its context often shrinks; some specialized division of labor can still help. The relationship is conditional, not monotonic.

CAPABILITY SATURATION · ROLE EXPERTISE
02

Task dependency

Embarrassingly parallel evidence collection differs from a tightly coupled code-editing or planning chain. Cross-agent handoffs can erase any benefit of parallelism.

DECOMPOSABILITY · CRITICAL PATH · MIN-CUT
03

Information bandwidth

A single agent retains its own history; multiple agents relay compressed summaries. The useful compression / missing context trade-off is central.

MESSAGE SUFFICIENCY · INFORMATION BOTTLENECK
04

Topology and routing

All-to-all communication can scale quadratically in directed message opportunities. Sparse, hierarchical, dynamic and verifier-gated graphs trade reachability for cost.

EDGE DENSITY · ADAPTIVE ROUTING
05

Selection and verification

Independent sampling requires an effective selector; collaboration requires mechanisms to detect wrong messages and stop propagation rather than merely share more text.

BEST-OF-N · VOTING · CHECKPOINTS
06

Budget and environment

Tokens, latency and tool-call volume create different Pareto frontiers. Agentic tasks require stateful actions; static math QA results do not directly transfer.

24 STUDIES
06 / RESEARCH PROGRAM

What would a real
scaling law measure?

From a paper collection to testable science. These are proposed experiments, not completed results.

RQ / 01

Map the capability–team-size phase diagram.

Vary base-model skill × team size × task coupling. Find regions where the optimal n* jumps from 1 to 2–4 or higher; report uncertainty and total cost, not just pass@1.

HYPOTHESIS · A TASK-CONDITIONAL OPTIMUM EXISTS
RQ / 02

Separate exploration from communication.

Compare single agent, best-of-N, self-consistency, independent ensemble, blackboard, peer, centralized, decentralized and hybrid under matched budgets. Control proposer and verifier quality.

IDENTIFICATION · ISOLATE THE COORDINATION DELTA
RQ / 03

Measure the value of an actual message.

Randomize senders, recipients, timing and content (score / summary / code / evidence). Compare incremental task utility with the same tokens spent on private reasoning.

CAUSAL ABLATION · MESSAGE MARGINAL VALUE
RQ / 04

Design task-adaptive organizations.

Route or create workers only when expected marginal benefit exceeds token, synchronization and error costs. Learn topology and stopping policy jointly with verification.

ALGORITHM · ADAPTIVE N, EDGES AND STOPPING
RQ / 05

Benchmark on true interactive tasks.

Use long-horizon code/research tasks with stateful tools; record verifier scores throughout execution, handoffs, contradictions, redundant work, latency, token use and final quality. Avoid reward hacking.

BENCHMARK · QUALITY–COST–RELIABILITY FRONTIER

Minimum protocol for credible MAS scaling claims

01 Hold fixed

Model family, tools, tasks, prompts, verifier, system-level budget.

02 Vary systematically

n, topology, rounds, routing, communication content, difficulty.

03 Track trajectories

Quality at each checkpoint, messages, tool calls, failures and wasted effort.

04 Report frontiers

Paired-task uncertainty, iso-token, iso-time and cost-normalized Pareto curves.
